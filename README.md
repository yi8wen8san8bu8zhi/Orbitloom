# Orbitloom

Orbitloom 是一款原生 macOS 本地项目与脚本管理工具。它将分散在不同目录的项目收录到统一资料库，帮助你记住项目用途、保存运行配置，并直接启动、停止和查看日志。

支持 Python、Node.js 和 Shell 项目及脚本，使用 SwiftUI、Foundation 和 macOS 进程接口实现，无第三方依赖。项目文件保留在原位置，Orbitloom 保存项目索引、配置和运行日志。

## 功能

- **项目收录**：手动添加目录或独立脚本，也可扫描多个目录，预览并勾选候选后批量添加。
- **本地信息识别**：从 README、项目声明、脚本头部和 Git 配置中提取用途、运行入口、环境要求及来源，并展示识别依据。
- **运行配置**：保存启动命令、附加参数、工作目录、环境目录、环境变量和可选的停止命令；后续刷新保留已保存的配置。
- **启动与停止**：支持一次性任务和常驻服务，展示运行状态，并管理由应用启动的进程。
- **日志查看**：实时查看、跟随和复制输出，保留每个项目或脚本最近一次运行的日志。
- **目录内脚本**：逐层浏览项目文件，为其中的脚本分别配置、运行和查看结果，无需逐个添加到左侧资料库。
- **搜索与整理**：按名称或用途搜索，使用标签筛选，支持单项及批量移除资料库条目。
- **路径恢复**：项目移动或删除后保留资料与配置，标记原位置不存在，并支持重新定位。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | macOS 26.4 或更高版本，取自当前工程的部署目标 |
| 开发工具 | 建议使用 Xcode 26.6 或更新版本；当前工程由 Xcode 26.6 创建 |
| 应用依赖 | 无需安装第三方 Swift 包 |
| 被管理项目的环境 | 按项目需要自行准备 Python、Node.js、包管理器及依赖 |

Orbitloom 不自动安装解释器、创建虚拟环境或安装项目依赖。运行项目之前，请先准备好它所需的环境。

## 构建与启动

在仓库根目录打开 Xcode 工程：

```sh
open Orbitloom.xcodeproj
```

在 Xcode 中选择 `Orbitloom` scheme 和 `My Mac` 运行目标，按 `⌘R` 构建并启动。如 Xcode 提示需要签名配置，在目标的 `Signing & Capabilities` 中选择自己的开发团队。

也可以使用命令行构建本地调试版本：

```sh
xcodebuild \
  -project Orbitloom.xcodeproj \
  -scheme Orbitloom \
  -configuration Debug \
  -destination 'platform=macOS' \
  -derivedDataPath /tmp/Orbitloom-build \
  CODE_SIGNING_ALLOWED=NO \
  build

open /tmp/Orbitloom-build/Build/Products/Debug/Orbitloom.app
```

上述命令关闭代码签名，适用于本机开发构建。

## 使用流程

1. **添加项目**：点击「添加项目」或按 `⌘O`，选择目录或脚本，填写名称、用途和可选标签后保存。批量收录时，打开「扫描发现」，添加扫描目录，勾选候选后点击「添加所选」。
2. **确认配置**：选择项目，点击「检查并配置」，核对识别到的入口、工作目录、运行方式和运行环境，补充所需变量并保存。
3. **启动与查看结果**：点击「启动」。目录主命令的输出显示在「运行日志」页签；独立脚本和目录内脚本的输出显示在主窗口底部的结果抽屉。
4. **停止运行**：运行中点击「停止」。收起结果抽屉或关闭主窗口不会停止项目；退出应用时，若仍有活动实例，会提示停止后退出。
5. **再次使用**：通过搜索或标签找到项目，使用已保存的配置直接启动。

对于包含多个脚本的目录，进入「文件」页签，点击支持的脚本并保存其运行配置。各脚本拥有独立的配置和日志，可通过「查看结果」或「已配置脚本与历史日志」重新查看输出。

添加扫描目录只保存位置；扫描后仍需确认收录。应用启动和「刷新已收录项目」只更新已有条目的识别信息与路径状态，不会自动新增项目。移除资料库条目不会删除原项目文件。

## 识别范围

| 类型 | 主要识别来源 |
| --- | --- |
| Python | `pyproject.toml`、`requirements.txt`、`setup.cfg`、常见入口文件、`.python-version` 及已有虚拟环境 |
| Node.js | `package.json` 的名称、描述、依赖、`scripts` 和运行环境声明；结合包管理器声明或锁文件生成 npm、pnpm、Yarn、Bun 命令 |
| Shell | `.sh`、`.bash`、`.zsh` 文件及可识别的 shebang |
| 通用信息 | README 简介及部分代码块命令、脚本头部注释、Git `origin` 地址和环境变量模板中的变量名 |

独立脚本支持 `.py`、`.js`、`.mjs`、`.cjs`、`.sh`、`.bash`、`.zsh`，以及带有受支持 shebang 的无扩展名脚本。

扫描会跳过隐藏目录、依赖目录、虚拟环境和构建产物，并在识别到项目边界后停止向下遍历。Maven、Gradle 声明也可作为项目边界，但尚无专用的 Java 运行环境与命令解析。SQL 文件仅显示类型提示，不提供数据库连接与执行。

识别结果用于提供配置候选；首次运行前需要核对。扫描和解析不会执行项目命令，也不会执行 `setup.py`。

## 运行配置说明

- **命令与参数**：使用 `/bin/zsh -f -c` 执行，支持 zsh 语法，以当前用户权限运行。当前工程关闭了 App Sandbox，请只运行已核对用途的命令。
- **运行方式**：一次性任务退出码为 `0` 时显示完成；常驻服务自行退出时显示失败，即使退出码为 `0`。主动停止显示已停止。
- **环境目录**：选择解释器或工具所在的 `bin` 目录，例如项目的 `.venv/bin`。该目录会优先加入 `PATH`；应用也会补充常见 Homebrew 和系统工具目录。
- **环境变量**：每行填写 `KEY=VALUE`。值按原文传递，不添加 shell 引号，也不进行变量展开。应用只从 `.env.example` 等模板提取变量名，不读取项目真实 `.env` 的值。
- **停止命令**：可留空使用应用的进程清理逻辑。自定义命令可使用 `ORBITLOOM_PID` 和 `ORBITLOOM_PGID` 定位当前实例。

命令不加载交互式 shell 的用户配置，也不提供终端输入或 PTY。依赖 `.zshrc` 中的别名、nvm 初始化、密码输入或交互式选择的命令，需要先调整运行方式。服务应保持前台运行，避免自行脱离应用管理。

## 本地数据

```text
~/Library/Application Support/Orbitloom/
├── library.json       # 项目资料、扫描位置、标签和运行配置
└── Logs/
    └── <UUID>.log     # 每个项目或脚本最近一次运行的日志
```

每份日志最多保留最新的 1 MiB，重新运行会开始新的日志记录。重启应用后可查看保存的日志，但不会恢复旧进程标识或运行状态。

环境变量值随配置以明文保存在本机，分享或备份资料库前应检查其中的敏感内容。备份应用数据时，可在退出应用后复制上述目录；原项目文件需要另行备份。
