# Orbitloom 首版实现说明

更新日期：2026-10-30

当前实现包含 requirements.md 的 P0 范围，以及后续确认的项目标签与过滤、目录内脚本运行功能。采用原生 SwiftUI、Foundation 和 macOS 进程接口，无第三方依赖。保留工程原有 macOS 26.4 最低版本。

## 使用方式

1. 在 Xcode 中打开 `Orbitloom.xcodeproj`，选择 Orbitloom scheme，运行 macOS 应用。
2. 点击左侧「项目资料库」旁的「＋ 添加」、顶部「添加项目」或按 ⌘O，选择项目目录或 Python、Node.js、Shell 脚本，填写名称和用途后点击「保存到资料库」。批量导入时点击「扫描发现」，查看候选的名称、路径、类型和识别依据，勾选后点击「添加所选」。扫描目录可在预览中添加、在设置中管理。
3. 在左侧按名称或用途搜索，通过与搜索框同一行、位于右侧的标签菜单选择「全部标签」「无标签」或具体标签；两种条件同时生效。筛选控件固定宽度，长标签单行省略显示，搜索框占据剩余空间。右侧查看简介、来源、本地识别结果及其文件来源。
4. 点击「检查并配置」，选择启动入口，核对工作目录、运行方式、已有环境和变量，确认并保存。
5. 点击「启动」，目录主命令在「运行日志」页签查看输出；独立脚本在主窗口底部结果抽屉查看输出。运行中可点击「停止」。
6. 在左侧点击「批量选择」，勾选项目或点击「全选当前结果」，再点击「移除已选」并确认数量。点击「取消」退出批量选择；右键单个项目仍可单独移除。
7. 手动添加项目时可填写标签，也可在项目详情「概览 → 项目标签」中点击「编辑标签」。输入标签、点击标签旁的 × 移除，或通过「使用已有标签」复用其他项目的标签，保存后生效。标签编辑不要求先配置启动命令，运行中的项目也可编辑标签。
8. 对于脚本文件夹，收录目录后进入「文件」，点击其中的脚本，在脚本面板中核对并保存配置，然后点击「启动」。启动后脚本面板关闭，执行结果从主窗口底部向上展开。配置只需首次确认。文件行、脚本面板及「已配置脚本与历史日志」中的「查看结果」可重新打开抽屉。

批量全选仅覆盖当前搜索和标签过滤结果中未运行的项目，运行中和停止中的项目不可勾选。搜索或标签过滤结果变化、已勾选项目开始运行时，会取消不再符合条件的勾选；扫描期间禁止移除。确认后一次保存全部移除结果，保存失败时保留项目和勾选并显示错误，成功后清理对应勾选及已移除项目的详情。

标签支持中英文逗号及换行分隔，去除首尾空白、空标签及完全相同的重复项，保留首次输入顺序；区分大小写，标签内空格保留。留空保存即可移除该项目的全部标签。编辑窗口使用独立草稿，取消不保存，写入失败时保留草稿与错误提示。移除某项目的标签不会影响其他项目。

列表显示前两个标签，其余以数量标记并可悬停查看；详情展示全部标签。筛选菜单汇总整个资料库的标签，不受搜索词影响。选中的标签不再被任何项目使用时仍保留当前筛选，显示「无项目」和空结果，用户可手动清除；不会自动扩大结果范围。无匹配结果时提供清除搜索和标签筛选的按钮。筛选条件仅保留在当前窗口会话中。

关闭主窗口不会自动结束项目；退出应用时，有活动实例会提示「停止并退出」。

手动添加先读取所选路径，预填名称和用途，选择文件本身不会入库。名称必填、用途和标签可留空；保存时重新读取路径，将填写内容与项目一起保存，运行配置仍待确认。重新选择成功后重置名称、用途及标签草稿。取消不收录，保存失败时保留表单草稿。重复路径提示「打开已有项目」，保留原有资料、标签和配置。保存或打开成功后清空搜索和标签过滤、退出批量选择并选中对应条目。

## 扫描与识别规则

- 应用启动和「刷新已收录项目」只读取已收录路径，更新识别信息与路径存在状态，不遍历扫描目录，也不新增项目。
- 添加扫描目录只保存位置。用户打开「扫描发现」时扫描已配置的目录，也可在预览中点击「开始扫描」或「重新扫描」；没有定时扫描或文件监听。
- 扫描结果只保存在当前预览窗口中，排除已收录路径，所有候选默认不勾选。只有「添加所选」才重新读取选中路径并一次保存到资料库；失败时保留候选和勾选，取消不会新增条目。新增的扫描目录仍保留。
- 扫描在后台进行。规范化路径并解析符号链接，合并重复或嵌套扫描位置；不同真实路径的副本分别收录。
- 遍历不跟随子目录中的符号链接，跳过隐藏目录、包目录、`node_modules`、虚拟环境、构建目录等。
- `package.json`、`pyproject.toml`、`requirements.txt`、`setup.py`、`setup.cfg`、`pom.xml`、Gradle 的 build/settings 声明（含 `.kts`）、`.git` 或常见 Python 入口标记项目边界。识别边界后不再下钻，候选展示命中的标记。
- 支持独立 `.py`、`.js`、`.mjs`、`.cjs`、`.sh`、`.bash`、`.zsh`，以及可识别 shebang 的无扩展名脚本。
- 候选扫描排除 `mvnw`、`gradlew` 构建包装脚本；手动添加仍支持这些脚本。扩展名和 shebang 只作为候选识别依据，不代表已确认可用的独立入口。
- Maven、Gradle 或 Git 仓库中不属于首版支持类型的项目可作为目录候选，但会显示「待识别」，由用户手动配置；没有增加 Java 运行配置解析。
- 自动提取 `package.json` 中的名称、简介、engines、依赖和 scripts，并根据声明或锁文件选择 npm/pnpm/yarn/bun 命令。
- Python 提取 pyproject 的常见单行元数据、控制台入口、常见入口文件、requirements、已有虚拟环境和版本声明。复杂依赖内容保留为带来源的声明文本；不执行 `setup.py`。
- 从 README 正文、代码块和脚本头部提取可识别的信息。README 的命令只是候选，不会自动执行。
- 环境模板只提取变量名称。不会读取或执行真实 `.env`，也不会自动判断模板中的变量都必需；用户应在配置中确认或删去非必需名称。
- 删除或移动文件后，下一次刷新会标记「原位置不存在」；原条目、备注和配置保留。重新定位后调整项目内的工作目录与环境目录，要求再次核对命令。包含旧绝对路径或旧脚本文件名的命令需要手动修正。
- 移除扫描位置不删除已有条目。从索引移除项目不删除磁盘文件；仍位于扫描目录的项目可再次出现在候选中，但必须重新勾选才会收录。历史误收录项通过现有批量移除功能清理，不自动删除其配置。

## 配置持久化

### 目录内脚本

目录浏览只读取当前层，在进入目录或点击「刷新」时更新，不递归扫描整个文件夹，不监听磁盘变化。隐藏文件、符号链接、应用包及既有扫描规则中的依赖和构建目录不显示。SQL 文件显示「需要数据库执行环境」，其他不支持的文件不提供运行入口。

点击支持的脚本时读取文件类型、shebang 和头部说明，复用现有配置编辑器与运行详情。脚本使用独立的 UUID、配置及日志；无需确认所属目录的项目启动配置，也不会在左侧新增条目。自动生成的命令引用脚本绝对路径，默认以脚本所在目录为工作目录，可按脚本用途另选目录。例如 `gitlab-group-clone.js` 使用当前工作目录作为克隆输出位置。

配置以项目内相对路径关联，保存在所属项目的 `scripts` 数组内；首次保存时生成确认记录，取消不会保存或启动。目录刷新和标签修改保留脚本配置。重新定位目录时，更新脚本配置中位于原目录内的工作目录与环境目录，取消所有脚本的确认状态；命令中的旧绝对路径需通过「选择识别到的入口」或手工编辑后重新保存。

文件页的「已配置脚本与历史日志」保留原路径记录。脚本被删除、改名或变得不可读时，不自动删除配置；原记录仍能查看日志、停止活动实例。改名后的新路径需要重新配置。运行状态按目录及其脚本汇总到侧栏，任何活动实例都会阻止移除或重新定位所属目录。目录的主运行配置与脚本配置彼此独立，脚本日志在底部执行结果抽屉查看。

### 资料库格式

资料库：`~/Library/Application Support/Orbitloom/library.json`。

自动识别信息与用户修改的名称、简介、类型、备注、标签、运行配置分开保存。保存成功后才更新界面；已保存的运行配置在刷新和重新定位后的刷新中继续保留。多个启动候选不预选默认命令。标签单独保存时只更新该项目的 `tags` 字段，不校验启动命令，也不改变运行配置的确认状态；刷新、重新定位及运行配置保存保留标签。

本次沿用版本 1 的资料库，新增项目级 `tags` 字符串数组。自定义解码仅为缺失或为 null 的标签字段提供空数组，其余字段保留原有读取规则；编码继续由 Codable 自动生成。旧资料库无需手工迁移，标签随下次正常保存写入。

目录脚本增量继续沿用版本 1，新增项目级 `scripts` 数组，缺失或为 null 时解码为空数组。每项包含稳定 UUID、相对文件路径和运行配置；旧资料库无需手工迁移。该兼容行为仅完成源代码核对，运行时持久化验收见验证记录。

资料库带版本号，使用 JSON 原子写入。读取失败或遇到不支持的版本时，显示错误并停止后续写入，保留原文件。资料库及日志文件权限为当前用户读写。

自定义环境变量使用每行 `KEY=VALUE` 格式，值不做 shell 求值，并以明文随本机配置保存。输入值不应包含额外 shell 引号。

## 启动环境与生命周期

- 命令使用 `/bin/zsh -f -c` 执行，stdin 指向 `/dev/null`。不加载交互式 shell 的用户启动配置。
- 继承应用进程环境，补充 Homebrew 和系统工具目录，再应用用户变量与选择的 bin 目录。常见 Python 虚拟环境会自动成为环境候选。
- 运行前检查首次确认、项目位置、工作目录、必需变量、选择的环境目录以及可识别的启动工具。
- 依赖包的兼容性和完整性不做穷举检查；实际命令报告的缺失依赖、导入错误、端口错误等会显示在日志中。不会自动安装环境、依赖或修改项目。
- 每个项目同时运行一个实例。每次启动通过 `posix_spawn` 原子创建独立进程组，stdout/stderr 合并捕获。
- 默认停止仅向本实例进程组发送 SIGTERM，3 秒未退出则发送 SIGKILL。入口进程退出时清理仍在同组的后代。
- 自定义停止命令在独立受管进程组中执行，获得本实例 `ORBITLOOM_PID` 与 `ORBITLOOM_PGID`。停止命令结束后仍会清理主实例，5 秒超时则强制清理。用户编写的停止命令本身必须限定目标，应用无法约束任意 shell 命令的外部副作用。
- 一次性任务退出码 0 显示「执行完成」，非零退出或信号退出显示「运行失败」。常驻服务自行退出（即使退出码为 0）显示失败。用户主动停止显示「已停止」。
- 运行模式由用户确认。可用性（待配置、位置不存在）和运行状态分别展示。

## 日志

脚本执行结果使用覆盖在主窗口底部的抽屉，宽度跟随窗口，高度为 320 点，以 0.22 秒动画从下向上展开、向下收起。抽屉显示当前脚本名称、路径、状态和实时输出，提供停止、跟随输出、复制日志及收起按钮；Esc 也可收起。收起只改变展示状态，不调用停止。查看其他脚本结果时切换当前抽屉内容，不重启或停止脚本。

目录内脚本启动或从脚本详情点击「查看结果」时，先关闭详情面板，再在关闭回调中打开抽屉。配置编辑保持现有弹窗方式。已配置文件行的结果按钮直接打开抽屉；从历史记录打开结果无需读取原脚本文件，文件失效也能查看日志和停止已有实例。移除所属项目后关闭对应抽屉。

独立收录的脚本也使用结果抽屉。目录主命令仍使用原「运行日志」页签，两处共用 `RunLogView`，沿用已有日志内容、滚动跟随和复制逻辑。

每个项目及每个已配置的目录内脚本分别保留最近一次运行的最新 1 MB，存储在 `~/Library/Application Support/Orbitloom/Logs/<项目或脚本 UUID>.log`。日志约每 250 毫秒更新，运行结束时立即保存，提供跟随输出与复制。

重新启动应用后，可以查看最近一次日志；旧 PID 和运行状态不会恢复。

## 已知边界

- App Sandbox 已按确认关闭；命令以当前 macOS 用户权限运行，首版供个人本机使用。
- 首版不提供 PTY 或 stdin 交互，不适合需要密码输入、交互式选择或终端 UI 的命令。
- 应以前台方式启动服务。不支持主动脱离进程组的守护程序，以及应用被强制终止、崩溃或系统断电后的实例恢复。
- 单个项目根目录中的嵌套项目不会全部自动展开，必要时可手动添加具体子项目。
- TOML 和 README 使用有限的明确规则提取，不是完整语法解释器，复杂项目需要手动配置。
- 标签支持单个项目编辑和单标签过滤；暂不提供批量打标签、全局重命名或多标签组合过滤。
- 暂无最近使用管理、共享依赖、Docker、账号体系或 AI 解析。
- 本次交付为本地 Debug 开发版本，未配置发布签名、公证或安装分发流程。

实际验证范围与结果见 `validation.md`。
